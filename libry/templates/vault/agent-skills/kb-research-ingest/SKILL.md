# kb-research-ingest — 研究→整理→确认→归档

> 这是一个**可改造的示例**：核心是确认门与管线结构，抓取命令按你的工具环境调整。

用户典型指令：「抓取这篇文章，分析值得学习的点，搜索类似资料，整理好经我确认归档」。

**核心原则：确认门（Confirmation Gate）** —— 用户要求「经我确认后归档」时，**绝不在确认前入库**。先产出待确认稿。

## 管线步骤

### 1. 抓取核心资料

- 网页文章：你的浏览器自动化工具或 `curl`；抓完核对 H1 是否为真实标题（抓取工具常见 `# untitled` 缺陷，入库前必须修正）。
- PDF/论文：直链下载后校验（`file` 类型 + 大小 + 页数）；**通读全文再分析**，只看摘要写不出「有待商榷」。
- GitHub 文件：`blob` 链接 curl 到的是 HTML；换 `raw.githubusercontent.com/<owner>/<repo>/<branch>/<path>`；404 时用 git/trees API 枚举真实路径（用户给的路径常已失效/有新版）。
- 暂存到 `raw/<分类>/`，同目录多文件注意互相覆盖。

### 2. 深度分析（结论先行，四段式）

1. **讲得对的部分** — 核心价值成立点，交叉验证（案例、社区共识、一手信源）
2. **有待商榷的部分** — 数据可靠性、幸存者偏差、隐含前提、法律/道德边界
3. **最有价值观点** — 按可迁移性排序
4. **个人应用建议** — 结合用户情况的可落地动作

**事实核查**：对文中引用的案例/数据用网络搜索找一手信源交叉验证，列事实表；警惕转述媒体的定性包装（「首次/最全/颠覆」），与原文自述不一致处标注 ⚠️。

### 3. 相关资料搜集

多路并行：社区观点（你环境里的站内搜索工具）、通用搜索（一手信源、**主动找唱反调的文章**）。整理为分组清单：一手信源 / 同类高价值文章（标题+作者+链接+一句相关性）/ 反面视角。

### 4. 待确认稿

写入 `output/<主题>-资料整理-待确认.md`：分析（四段式）→ 事实核查表 → 相关资料清单 → **拟入库方案**（source 页名、concept/entity 候选、index/log 计划）→ **待确认事项**（固定三项：分析是否 OK；相关文章入全文还是只留链接；concept 页建哪几个）。

**visibility**：用户不提默认 `shared`；原文含真人 PII/敏感内容时，加问附录处理方式（只放链接 / 附录但删 PII / 全文照录）并建议 `personal`。

### 5. 确认后入库

按 `kb-ingest` skill 与 `AGENTS.md` 执行（含第 0 步 purge 前置），完成后走 `kb-publish`。相关文章若只要链接：放 source 页「延伸阅读」区，不逐篇入库。

## 快速路由

用户给**本地文档路径**直接说「加入知识库」（无「分析/搜索/经确认」字样）时：**指令即确认**，跳过待确认稿与四段式，直接走 `kb-ingest` 流程。
